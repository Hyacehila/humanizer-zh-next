# 编辑边界与行为验证

这些材料检查技能是否保留内容和编辑范围，不检测作者身份。样例均为合成材料，不包含真实个人稿件。

## 自动检查

```bash
python scripts/validate_package.py
python -B -m unittest discover -s tests -p "test_*.py"
```

包检查验证元数据、版本、引用文件和固定提交的版权记录。单元测试验证结构辅助检查的实际作用：允许散文调整，捕获代码、公式、链接、数据、标题等变化；命令行不写入文件或打印原稿。

脚本不是完整 Markdown 解析器或语义评测器。复杂嵌套、特殊方言、HTML 与 LaTeX 项目要使用相应工具继续核对。列表标记一致不能证明列表含义和顺序正确。

## 行为案例

[behavior-cases.json](behavior-cases.json) 包含 17 条案例，覆盖真实编辑中容易发生的变化：

- 主张、数字、范围、否定、归因与未知施事者。
- 条件、顺序、同时发生、计划与已完成状态。
- 三项独立功能、作者声音、直接引语和混合情绪。
- 学术结果、研究计划、商务条件和已有对话背景。
- 审阅、改写和文件写回的范围区别。

评测执行者只接收 `request`、`input` 及提供的 `voice_sample` 或 `conversation`，再使用主技能和所需 references 完成任务。不要向执行者提供 `checks`、预期答案、此前失败或修改动机。

保存实际输出并独立核对 `checks`。没有固定的期望措辞；同一句话可以有多个合格改写。检查是否新增或遗漏信息、改变立场、跨越编辑范围，以及该保持原样的地方是否被强改。

教学例子和案例之间仍有共同问题类型；它们只能验证基本边界。增加未出现在技能中的独立长文、不同模型和重复运行，才能进一步观察稳定性。不要把一次通过写成准确率或保证。

## 文件案例

复制 [structure.md](fixtures/structure.md) 到隔离临时目录，让执行者润色副本。保留原稿用于只读比较：

```bash
python scripts/check_structure.py original.md edited.md --json
```

检查正文确实按要求处理，代码和数据不被执行或改动。即使检查通过，也要人工核对句意、步骤条件与引用关系。

## 记录结果

记录技能版本、执行时间、模型或环境（可见时）、实际输入、输出和核对结果，说明未验证范围。生成结果默认留在任务临时目录；不要把用户稿件、私有路径或个人样本加入公开仓库。

本轮实际检查与独立执行范围见 [2.0.0 本地验证记录](VALIDATION.md)。
